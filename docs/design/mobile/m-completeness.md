# Completeness sweep (whole main prototype)

## Not covered by any area
- Second prototype file is not covered by any area: 'FieldScout Mobile Lists and Rankings.dc.html' (593 lines, 112KB). It includes the Rankings hub, My rankings, New ranking, Ranking editor, Submit sheet, Lists grid, list editor and list view, which README covers under 'Screens (FieldScout Mobile Lists and Rankings.dc.html)'. Eight call sites in the main file navigate there with window.location.href. They are L1478 (global-search rank post to #view-<id>), L1537 (rankV.open to #view-<id>), L1549 (cmUpdates.open to #view-<id>), L1812 (Profile Lists rows to #lists), L1814 (Profile Rankings rows to #mine), L1816 (meNew to #new-list or #new-ranking), L1818 (Create sheet 'Ranking' to #new-ranking) and L1853 (notification row 2 to #view-r1). Without that file, every one of these exits leads to an undocumented screen.
- Legacy Players-tab model is computed but never bound. State: ptab:'trend', pos:'All', trendUp:true (L1414). Code: renderVals actOf (L1653), which only toasts and never opens the trade builder; pRows built from TREND/AVAIL/LEAD with per-row stats Rostered / Wk 4 pts / Wk 5 proj (L1654–1658); pTabs Search/Trending/Available/Leaders/Trade, where Search and Trade call soon() (L1659); pTitle, isTrend, notTrend, isLeaders, trendTabs Adds/Drops and posChips (L1738–1742). The bound Players tab reads only pf2/pview/pcols/psort. JUMPS #6–8 'Players · trending/available/leaders' (L1163, go() L1628) change only ptab, so all three show the same Players screen (pf2.status 'avail'). Only the jump-panel highlight (L1629) changes. Engineers should not build Trending/Available/Leaders sub-tabs.
- Dead 'Customize' sheet definition: renderVals const gridGroups (L1691–1695) has View (Projections 'Projected stats' / Stats 'Actual performance' / ADP 'Average draft position'), 'Week or season' (Season, Season avg, Week 5/4/3) and Year (2026–2023), plus state view:'proj', period:'Week 5', year:'2026' (L1415). The renderVals return never includes it. The bound sheet uses pVals.gridGroups (PCOLS groups, L1465). Someone reading the script top-down could build the wrong sheet.
- Players: trendSeg 'Trending | Recommended' segmented control (L1457, white 'on' pill with 0 1px 2px rgba(0,0,0,.12)) and state trendTab are computed but unbound; homeTrendAll (L1469) sets trendTab:'trend' with no visible effect. gridLabel 'Customize' (L1466) is also unbound; the markup hard-codes the text at L371.
- Match carousel affordances computed but unbound: mxLabel ('Your matchup' / 'Matchup N of 6'), mxPrev, mxNext and mxHint ('Swipe to see other matchups') at L1726–1727. Only mxDots and the swipe gesture are wired, which matches README's 'dots only, no label or arrows'. This should be recorded so nobody adds them back.
- leagueTabs (L1723): an in-header text tab strip (Match/Team/Players/League, active t1 with inset 0 -2px 0 #0088FF underline, click also sets swap:null) is computed but unbound. League tabs exist only in the dock.
- menuLeagues (L1855): a league list for the Menu sheet (name, 'team · rec', ini/av, active row bg var(--x-b1,#F5F5F7), click sets lg and closes the sheet) is unbound. The Menu sheet (L703–716) shows only lg.name as a section label above menuLeagueItems.
- League chat sheet is unreachable and its send path is broken. The sheet 'chat' (L717–723, title 'League chat', input placeholder 'Message the league') can only be opened by go(…,'chat') (L1628), and no JUMPS entry uses 'chat'. openChat (L1747) is unbound and would open the Messages screen anyway. Its send button calls the DM send() (L1696), which appends to threads[s.convo] (or does nothing if convo is null) and never to state.chat, so posted messages never appear in the sheet. The `msg` state is shared with the DM composer (L605/L723).

The Playoffs page note (L1796) promises 'The playoff bracket shows at the top of the League tab once the playoffs start in Week 15.' Confirm the League area's 'computed but unbound' list includes it.

## Cross-area inconsistencies
- Column tip naming conflict: Global §2.8 calls it a 'Column tip popover', but Players §2.7 calls it a 'Column tip modal'. In the source (L1108–1116) it is a centred modal card: scrim rgba(0,0,0,.18) at z30, card max-width 300px, padding 16px, radius 18px, shadow 0 12px 32px rgba(0,0,0,.2). It is not anchored to the column. It opens from strip chips in the list and cards views and from sheet column headers; c.sort opens the tip and does not sort (L1463).
- Transaction filters sheet has three owners: Players §2.9, League §2.6 and Global §2.5. The source never opens it from the Players tab. openFilters is bound only at L447 (League › Activity) and L528 (Transactions). The Teams section is hidden on 'My moves' (showTeamFilter = !myMoves, L1749). These three specs need to be merged into one.
- League settings overlay (hasSettings, L823–831) appears in Global §2.7, marked unreachable, and in Profile area T0 under 'Profile (Me), My start/sit, Settings'. In the source it is league-scoped (hard-coded title 'Sunday Funday League' / 'League settings', 13 SETTINGS tiles at L1339). It is unreachable: openSettings is unbound, and JUMPS #25 'Menu · league settings' uses sub 'menu', so it opens the Menu sheet. The Menu sheet's 'Settings' app row calls soon(). Both areas must agree, and the overlay must not be presented as Profile/app settings.
- Ownership is duplicated, so specs may diverge: the Notifications screen is in Global §2.10 and Home §2B; the DM composer in Global §2.6 and Messages §2.2; Trade detail (hasTd) in Messages §2.3 and Team §2.4 (D1–D3); the Create sheet in Community §2.13, Create flows §2.1 and Global §2.5; the league header in Match §2.1, League §2.0, Players §2.0 and Navigation 'Headers by screen'. Pick one owner for each and cross-reference from the others.
- Dock on non-league screens must be described the same way everywhere. Per L1708 and L1857, inLg = scr not in ['home','community','me']. That means Notifications, Messages, Thread, My start/sit ('myss'), Feed and Transactions all show the league tab bar (Match/Team/Players/League/Menu) with no item highlighted, because 'on' requires scr==='league' (L1709). The switcher is hidden there and barMt is -80px. This holds even when the screen was opened from Home, Community or Profile. Home §2C ('Bottom dock on these two screens'), Profile 'Global frame on these screens' and Navigation §(c) must all say this, not show the app tab bar on Notifications or My start/sit.
- Opponent-rank colour thresholds disagree within the source, so the Team and Players areas will differ. Team tab and swap-sheet rows use rk ≥ 20 green #07A852, ≤ 10 red #FF0028, else #FF8A00 (rowFor L1640). Players oprkC (L1440), profile games via tierOpp (L1206) and README use ≥ 23 / ≤ 10. Two other rules are separate: profile team ranks use ≤ 10 good, ≥ 23 bad (L1300), and the game-log rank uses ≤ 12 good, ≥ 24 bad (L1273). A single rule should be chosen for opponent rank.
- Notification counts disagree: the header badge is hard-coded to 3 (nUnread = notifRead ? 0 : 3, L1700), but 4 notification rows render unread (k < 4, L1853, with #F5FAFF background and a dot). Home §2B and Global §2.10 may each report a different number.
- README and prototype values that several areas will quote, at risk of being stated differently. Toast: README says about 2.2s; the code uses 1800ms with the timer restarting on each toast (L1624), bottom:100px, 36px tall (L1117). On league screens that position sits over the 68px switcher card (dock 68+80 = 148px). Sheet scrim: README says rgba(0,0,0,.4); the code uses .32 (L647). Swipe animations: README says about 200ms; the code uses 140ms linear for both the matchup and league swipes (L1728, L1771). Players: README says 'List/Sheet toggle'; the code has three views, list / cards ('Stats under each player') / sheet (L1460). Feed: README says 'plays open stat detail'; in the code a play tap selects that game (L1675) and box-score rows toast '<name> · player card' (L1686). Standardize on the code values.
- Global search overlay (hasGS, L1090–1107) is specified only in Match §2.4, but it opens from the Home header (L51) as well as the League header (L239). Its 'People' results for league managers call _openTeam, which opens the team-view overlay even over Home or Community (L1477). Results for other people jump to Community with cmSearch on and cmQuery set to the handle. The Home area and the Navigation graph must point to the same spec and behaviour.
- League sub-pages (hasPage, L891–957: My team, League settings/Scoring/Playoffs rows, Draft results with Round 1–6 chips, League history with All-time/2025/2024/2023, Previous seasons) are specified under Community §2.15. They are reached only from the League Menu sheet (openMyTeam L1783, menuLeagueItems L1784) and the unreachable settingsTiles (L1755). Global §2.5 (Menu contents) and Navigation must link to Community §2.15 rather than respecify it. The Menu rows Notifications, Co-owners, Commissioner note and Stat corrections only toast '<label>: screen coming next'.
