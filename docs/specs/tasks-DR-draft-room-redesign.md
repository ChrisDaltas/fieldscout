## 2. Chris's requirements (verbatim — these are rulings, not suggestions)

1. *"the 'Draft Board' needs to go full width"*
2. *"The Available players, Queue, Roster, Lists Chat should all be tabs across the bottom of the screen that slide up and down. so the user can have a focused view on just the draft board."*
3. *"'You're on the clock' needs to be moved to the left side of the div"*
4. *"the page header that says 'Draft Room' can go away, move the Live, Round, Draft order all up to the top of the screen"*
5. *"the Draft Room should open into it's own tab and not have the right hand context bar or the navigation bar on the left side. The draft room is a full screen experience."*
6. *"If the user is logged in as the Commish at the very top of the page there should be a black bar 54px tall, full width with buttons to Pause, Resume and a Draft Options menu that lets the user change the clock timers or any of the other fixes."*
7. *"If a user is not the commishioner that top bar will show the draft status like 'Draft Paused by Commish' and it will also have the Exit Draft button in the top right corner."*

**Rulings on the Architect's clarifying questions:**
- **Draft Options absorbs the ENTIRE commissioner panel** — timers PLUS undo, cascade undo, reassign/move a pick, force pick, edit order, Manual Edit Mode, reset, End Draft. The separate "Commish panel" button goes away.
- **Sequencing: redesign first, auction engine continues behind it**; the auction UI then builds into the new shell.
- **Opening behavior (resolved in chat after Chris pushed back on the Architect's first recommendation):** the ROUTE is a standalone chrome-free page that works on click, deep link, or refresh. **In-app entry on DESKTOP opens a NEW BROWSER TAB; on MOBILE it opens in place.** Chris: *"I was hoping it would just load the page in a new browser tab."* The two-tabs case is to be **designed for, not ignored**.
- **Exit Draft appears for BOTH commissioner and non-commissioner** — everyone must be able to leave.
- **Notifications do NOT deep-link into the room** (2026-08-17): *"the notification can take the user to the homepage where they can hit the Join Draft button."*
- **Chrome-free scope — the lobby and live room yes, the recap no (2026-08-17; PROGRESS §3 Q12):** *"having a bunch unnecessary UI mid draft doesn't make sense… you need all the space you have for the draft surfaces"* — naming ESPN, Yahoo and Sleeper. **The reason is the rule:** the full-screen treatment exists because the LIVE surface is space-hungry. The recap is not a draft surface (it is a reading page revisited days later) and keeps the app shell.
- **Exit Draft hands your picks to the engine, and that is the point (2026-08-17; PROGRESS §3 Q13):** *"Exit draft just exits you from the draft room and after a certain amount of time puts you into 'auto draft' mode. Which is how all mock drafts work."* Mechanically: navigate in place, no `window.close()`, no confirmation — and **the away path is the heartbeat's (D102), NOT the persistent `is_autodraft` toggle**, so returning restores manual control immediately (DR.2).
- **Two tabs — newest wins (2026-08-17; PROGRESS §3 Q14):** *"The most recent one takes over and the others disconnect."* The takeover guard is ruled, not proposed (DR.6).

## 3. Design decisions (Architect; **D147–D156** — they enter PROGRESS §4 verbatim when this PR merges, the D126–D143 precedent)

- **D147 — The room escapes the shell by moving the guard up, not by duplicating it.** `src/app/app/layout.tsx` today does auth + username gate + `<AppShell>` in one component (:12–40). It splits: the **layout keeps the guards and becomes a pass-through**, and `<AppShell>` moves down into a route group `src/app/app/(shell)/layout.tsx` that holds every existing route, with the room in a sibling group `src/app/app/(room)/leagues/[leagueId]/draft/`. **Route groups do not affect URLs**, so `/app/leagues/[id]/draft` is unchanged — no redirect, no link rewrite, no broken deep link, and the `DraftBar`'s own-room path check keeps working. Chosen over the alternatives deliberately: a `usePathname()` conditional inside `AppShell` would make every app route pay for the room's special case and would still mount the shell's providers; a separate top-level `/draft/…` URL would break every shipped link and the spec's §16.1 route table. **The guard is not duplicated into two layouts** — one copy, above both groups, is what keeps cold-load auth honest (D148).
- **D148 — Cold-load correctness is an acceptance criterion with a named adversary.** A new browser tab is a server-rendered cold start with no client history, and so is a refresh mid-draft; the new-tab ruling makes this the *primary* path rather than an edge case. **Observation recorded 2026-08-17 (Chris, in two browsers):** loading the live draft URL directly bounced to `/app?redirect=%2Fapp%2Fleagues%2F…%2Fdraft` while in-app click-through worked. Two mechanisms exist and the Builder must distinguish them by evidence rather than assume:
  **(a) the dev-auth artifact (likely, and benign in production).** `devAutoLogin` (`src/lib/supabase/dev-auth.ts:26–45`) is a **client-side** `signInWithPassword`. On the very first cold load of a fresh browser there is no session cookie yet, so the server sees an anonymous request and `middleware.ts:36–42` redirects; the browser then signs in, and every later request has a cookie. That produces exactly the observed two-hop shape (`/app/leagues/…/draft` → `/login?redirect=…` → middleware's :45–50 branch sees a user, rewrites the pathname to `/app` and **keeps the search params** because it clones `nextUrl`, landing on `/app?redirect=…`).
  **(b) a real, production-plausible defect found while diagnosing (a).** `src/middleware.ts` writes refreshed auth cookies onto `supabaseResponse` via `setAll` (:18–27) but **both redirect branches return a brand-new `NextResponse.redirect(...)` (:41 and :49), which does not carry those cookies.** This is the documented `@supabase/ssr` footgun: a cold load holding an expired-but-refreshable token can be bounced *and* lose the refresh. It is not reachable through in-app client-side navigation, which is exactly why the redesign — whose primary entry is a cold tab — is what would surface it.
  **The task's obligation is to prove which one it is, on a real (non-dev-auth) session, and to leave a test rather than a memory** (DR.1, DR.8). Filed as ledger row **F61** so the routing is findable. *(Recorded but out of scope to celebrate: `login/page.tsx:24/:51` does honor `?redirect=`, so once a user logs in they do land in the room — the destination is preserved through the login page and lost only by middleware's `/login → /app` rewrite.)*
- **D149 — Three zones, two bands of chrome, and the on-the-clock line resolves INTO the status strip rather than becoming a third band.** The brief flagged three candidates competing for the top (the 54px bar, the Live/Round/order strip, and the on-the-clock line). They resolve to **two**: the command bar (54px, ink, pinned) and the status strip (`h-header` = 58px, the existing token). Chris's "move it to the left side of **the div**" is read as the div it already lives in — the status strip's flex row (`snake-draft-room.tsx:719–765`), where it currently sits **right-aligned next to the clock** (:743–759). Moving it left makes one band whose two ends read *whose turn* and *how long*, which is a better answer than a dedicated band and costs 112px of vertical chrome instead of ~170px. **A third band is out of scope and a Builder proposing one has left it.**
- **D150 — The dock is a NON-MODAL drawer, and that single choice settles most of its behavior.** The panels overlay the board; the board, the clock, the command bar and the presence strip stay visible and operable behind them. Therefore: **no focus trap, nothing `inert`, no scroll lock, no backdrop that swallows clicks** — a user must be able to watch the clock while browsing the pool, which is the entire draft-night workflow. Escape closes; clicking the active tab toggles it closed; **exactly one panel is open at a time** (two open panels is a rail again). Focus moves to the panel on open and **returns to the tab button** on close. Default state is **closed**. **This is deliberately NOT the shipped `Sheet`/Radix Dialog primitive**, which traps focus and marks the rest of the page inert by design — using it here would make the board unreadable while the pool is open. The dock is a plain positioned region with `role="tabpanel"`/`aria-expanded` wiring, not a modal.
- **D151 — Open height is fixed, and the board never resizes.** The open panel occupies a fixed fraction of the viewport (`min(60vh, …)` desktop / ~75vh mobile — the Builder pins the exact token) and is **absolutely positioned over** the board. The board's own geometry — the grid's `minmax(96px, 1fr)` columns and its horizontal scroll (`draft-board-grid.tsx:53–105`) — **must not change when a panel opens or closes**: a board that re-lays-out on every tab press is the thing a full-width board was asked for to avoid. No drag-to-resize in v1 (a resize handle on a drawer that overlays a horizontally-scrolling grid is a pointer-conflict problem worth its own task, not a freebie).
- **D152 — Elevation: the dock panels and the command bar are BOTH sanctioned resting shadows, and each says why in a comment.** CLAUDE.md's ruling is that nothing in normal flow rests elevated and shadows appear only behind an interaction prefix — **with an explicit exception for true overlays and for bars pinned over scrolling content**. The dock panels are true overlays (they float above the board); the 54px command bar is pinned chrome over scrolling content. Both therefore keep a resting `shadow-hard-*` **with a comment naming the exception**, exactly as `src/components/ui/elevation-rule.test.ts:38`'s `OVERLAY_FILES` allowlist requires of shared primitives — and any new file the test's sweep covers is added to that allowlist with its reason, never silenced. **Everything else the redesign touches obeys the ordinary rule:** the status strip does not rest elevated, and selected/on-the-clock/active states stay carried by fill (`bg-accent-soft`) or border (`border-accent`), never by a shadow.
- **D153 — `Draft Options` is a menu over the SHIPPED panel body, not a reimplementation of it.** CLAUDE.md forbids near-duplicate components, and `commish-draft-panel.tsx` is 956 lines of working, reviewed, refusal-aware controls. The menu lists the control groups; choosing one opens the existing panel at that section. **What actually changes in that file is its trigger** — the blue `Commish panel` button (:120–123) is deleted and the panel becomes trigger-less, opened by the bar. The eight sections keep their bodies, their gates, their confirm dialogs and their system-post semantics. **Nothing about §8.7's control semantics changes in this lane** — no new refusal, no relaxed one, no altered audit or chat behavior.
- **D154 — On a mock, the command bar is the launcher's bar, because a mock has no commissioner.** `isCommish` is already `false` on every mock (`snake-draft-room.tsx:443`, D110(1)). The bar's three variants are therefore: **commissioner** (Pause/Resume + Draft Options + status + Exit), **member** (status + Exit), **mock** (MOCK identity + status + Exit, plus — for `config.mock.launched_by` only — Pause/Resume practice and a reduced *Practice options* menu carrying delete-and-exit). The `MockBanner` at `:712` is **absorbed into the bar** rather than stacked beneath it (§16.5.4's v2.12 note): a permanent bar plus a permanent banner saying the same thing is the duplication §16.3's say-a-thing-once rule exists to stop. **No commissioner control becomes reachable on a mock** — the reduced menu carries only what D110(1) already permits the launcher.
- **D155 — The pause overlay stops narrating and starts illustrating.** With the bar announcing "Draft paused by @commish" for everyone, `DraftPauseOverlay`'s duplicate copy is retired; the board keeps a *visual* paused treatment (dimmed, non-interactive) and the clock keeps its shipped paused rendering (`pick-clock.tsx`'s paused mode). **The Resume affordance moves to where the actor is** — the bar's Resume button for a commissioner, the same for a mock's launcher — so `canResume`/`onResume` (`pause-overlay.tsx:38`, wired at `snake-draft-room.tsx:604`) lose their button rather than their meaning. One state, one voice, one place to act.
- **D156 — The two-tabs guard is a courtesy over a correctness boundary, and is scoped to say so.** *(**RULED by Chris 2026-08-17** — "The most recent one takes over and the others disconnect"; PROGRESS §3 **Q14** Resolved. This decision is now built, not proposed.)* The server is authoritative (§8.1), so two tabs can never corrupt a draft — a stale tab's action is refused by the same validators as anyone else's. What two tabs *do* cost is real but bounded: two sockets and two `draft:<id>` subscriptions against §9.3's ≤3-channel budget, two `draft_touch` heartbeats, and a presence list that shows one manager twice (presence is keyed by team id — `use-draft.ts:244`). The guard is therefore **client-local leader election** (`BroadcastChannel` keyed by draft id, `localStorage` fallback): newest tab holds the room, older tabs unsubscribe, stop the heartbeat, and render a takeover state. **Per browser profile, not per user** — a laptop and a phone are two legitimate clients and are left alone. **It adds no channel, no route, no server state.**

## 4. Standing rules for every DR task

1. **The spec wins.** §16.4's layout callout is the contract; if the code and the spec disagree, the code is wrong. Ambiguity → PROGRESS §3 with a recommendation, never an improvisation (CLAUDE.md).
2. **Re-skin and rehost in place — never fork.** The five panels, the board grid, the pick clock, the presence bar and the commissioner panel are **moved and restyled, not rebuilt**. A new component is justified only for chrome that does not exist today (the bar, the strip, the dock, the options menu, the guard hook — the five §16.2 additions and no more). A "small visual difference from the design" never justifies a sixth.
3. **Design system discipline (CLAUDE.md):** single blended theme — **no `dark:` variants, no `next-themes`**; Tailwind v3 tokens only — **no arbitrary hex, no `shadow-[…px…#hex]`**; the app's **×0.8 scale** (convert handoff numbers down; 54px and 58px here are literal app-space numbers Chris gave against the running app, not 1× handoff values — see §8).
4. **Elevation per D152.** Interaction-prefixed shadows everywhere except the two sanctioned resting cases, each commented; state is fill or border, never shadow.
5. **No data-layer changes.** No migration, no RLS, no RPC, no route handler, no change to `use-draft*.ts`'s fetching, reducer, channel, or heartbeat semantics. DR.6 *releases* a subscription; nothing opens one.
6. **Every state, every width.** §16.5.4's required states apply to every surface a task touches — skeleton, empty (designed copy), error-with-retry, degraded/reconnecting — and the room must be checked at mobile, tablet and desktop, because the redesign is the first time the room's own controls exist below `lg` at all (§1).
7. **Evidence is prose + DB corroboration (R278).** "Browser pass" in a DoD below means that form. A claim that a state renders is not evidence that it renders.
8. **One task, one PR, off `main`, never committed directly** (CLAUDE.md). DoD = delivery plan §2.3: tests green *shown, not claimed*, PROGRESS updated, small commit citing the spec §.
