> **This lane overturns a rule that was correct when it was written.** D103/D110(1) closed every §8.7 commissioner control on a mock because it read them as *interference with a member's solo practice* — one member reaching into another's rehearsal. That reading was right about authority and it caught a real bug (an unguarded `draft_reset` was live-proven to write the league). What it missed is that **in a mock the launcher and the commissioner are the same person**, so there is nobody to interfere with. Chris ruled it: the solo driver is the commish of their own sandbox.
>
> **What is NOT overturned: §8.8's zero-side-effects rule.** A mock still writes nothing to the real league. That rule is the *reason* D103 caught something real, and it is this lane's gate on every task (§4 rule 14). **The audit finds which controls can pass it — it does not assume `draft_reset` is the only one that cannot.** As of this survey, **four** of the fifteen-mechanism §8.7 surface are structural breaches, not one — and the fourth is the worst, because its guard exists, reads correctly, and **never runs** (§1.3/§2.3).
>
> **The spec is LAW.** Where this document and v2.15 disagree, v2.15 wins and this document gets corrected.

### 1.2 The launcher-authority idiom already ships, and it is NOT `resolveActingSeat`

- **The pattern to copy is `draft_pause` / `draft_resume`** — `069:404–415` and `069:458–468`, a two-part gate:

### 1.3 The API layer — nine words that hid a breach, and what is actually true

> **This heading used to read *"The API layer needs almost nothing."*** It is corrected in place rather than deleted, because the sentence was not merely wrong — **it was the premise that made §1.3's own fourth breach invisible**, and an audit built on it (MS.1's first draft) would have certified the control as clean. The true statement is narrower: *ten of the eleven controls need no route change; the eleventh needs a route change precisely because it never had a route parameter.* R469's rule follows from it — **measure through the surface a user reaches the control by, not only through the RPC.**

- **One pipeline already reaches a mock.** `dispatchControl` (`draft-service.ts:1070–1094`) parses → `resolveDraftForAction` → RPC over a closed union. `resolveDraftForAction` (`:317–341`) applies `.eq('is_mock', false)` **only on the no-`draft_id` probe**; with an explicit `draft_id` — which a mock room always sends — there is no mock filter and no status filter. So ten of the eleven verbs already reach a mock's `draft_id` and are refused only by the RPC.
- **The routes carry no authorization at all** — `…/draft/clock/route.ts` is auth-check → `setClock(supabase, id, body)`. Server-authoritative, in-body, as §12/§4.1 require. **No route file changes for MS.2.**
- **`draft_set_order` is the one exception, and it is the lane's FOURTH structural breach — it is MIS-TARGETED, not blocked.** The order edit is not in `ControlRpcName`; it rides the draft **PATCH** (`patchDraftOrder`, spec erratum v2.8.17/D114). **Its request carries no `draft_id`** — `orderRequest(leagueId, order, reason)` builds `{ order, reason }` and nothing else (`use-draft-controls-ops.ts:247–256`), and it is **the only draft control that omits one: measured 11/11** for the `dispatchControl` verbs (`awk` over every `…Request(` builder in that file; `memberAutodraftRequest` also omits one, and it is §2.2's other breach). So `patchDraftOrder` picks the target itself — `.eq('league_id', leagueId).eq('is_mock', false).in('status', ACTIVE_DRAFT_STATUSES)` at **`draft-service.ts:198–204`** — and hands *that* id to the RPC at **`draft-service.ts:260–264`** (`p_draft_id: draft.id`).
- **The consequence, and it is the opposite of harmless — this is the bug, and it is LIVE TODAY.** `draft_set_order`'s own mock refusal exists in `prosrc` and is at `087:2341` — **and can never fire, because the RPC is never handed the mock.** A commissioner practising in their own league who edits the order from the mock room rewrites **the REAL draft's order** and posts *"Draft order updated by …"* into **the real draft's room**. **Probed here** (rolled-back txn, minimal fixture — one league, a real `live` draft `…d1`, a mock `live` draft `…d2`, then `patchDraftOrder`'s resolver verbatim): the resolver returns **`…d1`, the REAL draft**, never the mock. An RPC-level fix therefore cannot work — **the correction has to be service-layer** (§5 **MS.7**).
- **WHY THIS BUG IS SEVERE, and it is not the row count.** A draft order is **negotiated property**. Chris, 2026-08-20: *"two people text messaging agree to swap picks"* — managers bargain over slots off-platform and the commissioner records the result. **Silently reversing a stored order destroys something people agreed to**, and nobody in the room is told: the write posts *"Draft order updated by …"* into the **real** draft's chat, so the transcript reports it as an intentional commissioner act. That is worse than a lost row, and it is the reason this is a blocker rather than a tidy-up.
- **The remedy is NOT exclusion — Chris ruled the control must WORK in a mock (D222).** An earlier revision of this document excluded `order` and put it on MS.5's must-not-render list; **that is overturned.** See D222 for the parity principle and §5 **MS.7** for the fix.
- **Reachability today, stated precisely so the sequencing is not guessed:** the endpoint answers, but the mock room does not offer the control (`draft-room.tsx:704`'s `&& !draft.is_mock` masks the Draft Options menu), so today it is a **latent** bug reachable only by calling the route directly. **It becomes a one-click bug the moment MS.5 renders the group** — which is why **MS.7 lands before MS.5** (§9).
- **Two §8.7 panel sections are not `draft_*` RPCs at all** — see §2.2.

### 1.4 What each control writes (measured against the deployed schema)

Direct write targets, extracted from `pg_proc.prosrc`:

```sql
SELECT p.proname, string_agg(DISTINCT m[1]||':'||m[2], ', ')
FROM pg_proc p JOIN pg_namespace n ON n.oid = p.pronamespace,
     LATERAL regexp_matches(p.prosrc,

WHERE n.nspname = 'public' AND p.proname LIKE 'draft%' GROUP BY 1 ORDER BY 1;
```

The result is in §2.1. **Direct statements are not the whole answer** — three of the controls reach further through helpers, and the call graph must be followed:

- `draft_end` → `draft_complete_internal`, which writes **`league_rosters` and `leagues`** — but **already inside `IF NOT v_draft.is_mock THEN`** (measured: the guard wraps both writes). So the completion breach is closed at the writer, not at the caller. 041 §J (R467) pins that a mock completing through AP.2's new route leaves the whole `leagues` row byte-identical.
- `draft_force_pick` → `draft_apply_pick_internal` → `draft_complete_internal` (same guard) and, since AP.2, `draft_award_nomination_internal`.
- `draft_undo` / `draft_cancel_nomination` → `draft_void_nomination_internal` (`draft_bids`, `drafts` — draft-scoped).
- **A side effect is not only a row.** Every one of `drafts`, `draft_picks`, `draft_bids`, `league_chat`, `leagues`, `league_rosters` carries a broadcast trigger (`pg_trigger`, non-internal). Measured: `broadcast_draft_update` sends to `'draft:' || NEW.id`, `broadcast_league_chat_insert` routes on `NEW.context LIKE 'draft:%'` and otherwise to `'league:' || NEW.league_id`. So a mock-scoped write reaches only the mock's own topic — **and `draft_reset`'s `UPDATE public.leagues` fires `tr_broadcast_leagues` onto the `league:<id>` topic, which every member of the real league is subscribed to.** §8.8 isolation therefore has a *topic* dimension as well as a *row* dimension; MS.1 measures both.

### 1.5 `draft_reset` — the breach, and why a mock-safe variant is not a subtraction

`draft_reset`'s HEAD is **087:2481–2615**. Its writes, in order: `draft_picks` soft-undo · `draft_bids` void sweep (R379/D162) · `league_chat` system post · the `drafts` row back to pre-draft · `DELETE FROM draft_liveness` · and then

```sql
UPDATE public.leagues SET
  status     = 'scheduled',
  settings   = settings #- '{draft,draft_scheduled_at}',
  updated_at = now()
WHERE id = v_draft.league_id;
```

(`087:2604–2608`, with the D107(5) reasoning in the comment above it). It also takes `FOR UPDATE` on the league row at `087:2529–2531`. **D110(1) live-proved the breach** — *"main's unguarded draft_reset restored in a rolled-back txn: reset(mock) flipped the league `setup`→`scheduled` AND removed `settings.draft.draft_scheduled_at`"*.

Two facts make the variant a design problem rather than a deletion:

- **`drafts.status = 'scheduled'` is a state a mock cannot leave.** `draft_start_internal` filters `AND d.is_mock = FALSE` (measured, twice in the body), so neither the Start button nor `draft_tick`'s D94 auto-start arm can restart it. A reset mock would be **permanently stuck**.
- **…and the room has a rendering for it, which is the wrong one.** `draft-room.tsx:415` is `if (draft.status === 'scheduled') return <DraftLobby …/>`, mounted with `isCommish={canUseCommishPanel(detail.data.my_role)}` at `:427` — **no `!is_mock` mask on that mount**, because a mock has never been `scheduled`. A reset mock would render the real draft's pre-start lobby, offering a Start that cannot fire.

So a mock-safe reset must return the mock to **`live` at pick 1**, not to `scheduled`. That is a different write, not a removed one. §5 MS.4.

### 2.3 The count, stated plainly

**The counting rule, stated so the arithmetic is reproducible** (an earlier draft of this section said "fourteen" over a list that sums to fifteen, and MS.1 item 1 gates on the number): **count by MECHANISM — one entry per distinct server verb a §8.7 control reaches** — because that is what a `pg_proc` sweep reproduces and what an audit can drive. - **2** already-open launcher verbs — `draft_pause`, `draft_resume` (§2.1 rows 12–13).
- **2** panel sections reaching league verbs — the autopick toggle and seat reassignment (§2.2).

*(`delete_mock_draft` is listed in §2.1 for completeness and is **not** counted: it is a mock-lifecycle verb, not a §8.7 control. **But failing §8.8 today is a statement about the CODE, not a disposition — and the two are different.** Three are **EXCLUDED** (`draft_reset` pending MS.4's decision; the autopick toggle and seat reassignment permanently, since they write the real league by construction). **`draft_set_order` is FIXED AND ENABLED** — Chris ruled that a mock must be able to set its own order (**D222**), so the mis-target is corrected at the service layer rather than papered over with a refusal. **The safety argument that would have excluded it lost to the parity argument, and D222 records why.** Everything else in the table is *provisionally* mock-local **by code read**, which is not the standard: **MS.1 converts every "mock-local" cell above into a measurement or removes it from the cleared list — and it must measure through the ROUTE, not only through the RPC, or it cannot see this class at all (§5 MS.1 item 3).**

## 3. The rulings this lane exists to implement (Chris, 2026-08-20 — verbatim)

1. *"in a mock my assumption was that the solo person is the commish so the user running the mock should be able to make it as fast as possible IMO and pause it if they need to do something. that's kind of the point of these mocks…"*
2. *"these mocks just get deleted when they're done so it really doesn't matter. if anything it could be a good way for random people to know what tools a commish has."*
3. On explanatory copy — **"no."**
4. Earlier the same day, governing the whole lane: *"a commish can pause a draft and change anything or someone can disconnect at any time. TBH in drafts that's known as a 'personal problem'."*
5. **Ruled after this document's first review, on the draft order — and it is the general rule the lane now rests on:** *"so the point is the commish will need to set the draft order no matter, and it can always change last second. so there needs to be a way for the commish to set the order and then if real leagues can a mock league should as well so everyone can simulate their actual draft position or test different ones if they have a choice. for example, in my league last place gets to choose their draft position the next year."*

7. Correcting the Architect's assumption about when an order exists: *"there is no real draft order, most drafts will set the order right before."*

**What each one settles.**

- **(1) is the scope and the reason.** The launcher is the commissioner of their own sandbox, and the two things named — *make it as fast as possible* and *pause it* — are the clock and the pause. Pause already works (D110(1)); the clock is D141's carve-out (MS.3).
- **(2) is the answer to "is this worth building".** A mock is disposable, so the blast radius of a commissioner tool inside one is zero — provided §8.8 holds. Discovery is a *bonus he noticed*, not a feature to build. See (3).
- **(3) settles the copy question and it is CLOSED — do not reopen it.** No teaching label, no "these are the tools a commissioner has" line, no tutorial, no onboarding hint, no first-run tip. The tools are simply present and work. **MS.5's bar is that the controls are FINDABLE, not that they are EXPLAINED**, and no task may add copy to compensate for placement.
- **(5) is PARITY, and it is the strongest rule in the lane — it OVERRIDES the safety instinct.** A mock gets whatever a real league gets. Not *"if it happens to be safe"* — **a mock that cannot reproduce the user's actual draft position is not practice, it is a different draft.** His last-place-picks-their-slot league is the motivating case: someone with a genuine choice of slot has to be able to *try* each one, against a real clock, before deciding. This reverses what an earlier revision of this document did with the `order` control — it excluded it because it was unsafe, which answered the wrong question. **The right question is "how do we make it work", and the answer is D222 + MS.7.**
- **(6) is the severity note, and it belongs beside the fix.** A draft order is **negotiated property**: managers bargain over slots off-platform and the commissioner records the result. Silently reversing a stored order destroys something people agreed to — which is what §1.3's bug does, while posting a system line that makes it look intentional. It also names a control that does not exist: a **swap**. That is **F101**, filed and explicitly **not built in this lane** (§6).
- **(7) corrects an Architect assumption and it changes MS.8's design.** *Most leagues have no order when a mock is launched* — so the undrawn case is the **normal** one, not the edge, and a mock cannot express "put me third" by inheriting an order that does not exist. See **D223**.
- **(4) forbids defensive machinery.** Nothing in this lane specs a confirm-you-really-meant-it flow, an are-you-sure over a clock change, an undo-the-undo, or a reconnect-safety net for a human who changed their mind. A commissioner changing things mid-draft and a manager dropping off are *the normal case*, and the engine already handles both. **A "safety" feature that (4) rules out is scope creep with good manners.** (This does not touch the *engine's* correctness guards — solvency, locks, idempotency and the §8.8 gate are not "defensive machinery", they are the contract.)

#### D217 — What D103 got right, what it missed, and the exact shape of the overturn

1. **D103/D110(1) were right about authority and right about the bug.** "A commissioner control on a mock is interference with a member's solo practice" is a correct sentence about a commissioner reaching into *someone else's* rehearsal, and the guard caught a live-proven `leagues` write. Neither of those is being called a mistake.
2. **What it missed is that in a mock the launcher IS the commissioner.** The doctrine was written from the *actor* side (who is reaching in) and never asked what happens when there is only one person in the room. Chris's ruling 1 supplies the missing premise, and the whole lane follows from it.
3. **The overturn is scoped to identity, not to isolation.** What changes: *who* may call a §8.7 control on a mock. What does not change: **§8.8's zero-side-effects rule** (unweakened, and now the explicit gate — D218), **D103(2)'s no-other-driver doctrine** (a commissioner who is not the launcher still gets nothing — MS.2 item 7 pins it), and every real-draft behaviour (§4 rule 13).
4. **The pattern is already in the codebase and it is 069's, not `resolveActingSeat`'s.** `draft_pause`/`draft_resume` solved this exact problem at L.B1.6 — member floor, then commissioner for real drafts, then launcher for mocks. MS.2 extracts that into one helper and applies it. The working draft of this document proposed reusing R420's `resolveActingSeat`; that is a **TypeScript API-layer seat resolver** for the F65 response-integrity check, not a server-authoritative gate, and reusing it would have put authorization in the wrong layer (§1.2).
5. **The gate ORDER is the load-bearing bug, and it is measured.** In all eleven controls `is_league_commish` fires before the mock refusal, so today's friendly P0001 is unreachable for a non-commissioner launcher — the exact person this lane is about. D110(1) recorded the consequence in one clause and nobody had a reason to act on it until now. **The reorder therefore runs at ALL ELEVEN sites, cleared AND excluded** — E75 (LAW added by this same PR) requires an excluded control to refuse *"with a message that names its own reason"*, and measured, `draft_reset` and `draft_end` answer a non-commissioner launcher with `42501 not a commissioner of this draft's league`. A reorder scoped to the cleared set would ship LAW the code cannot honour.

#### D218 — §8.8 is the gate, it is answered by measurement, and `draft_reset` was not the only breach

1. **The audit is its own task (MS.1) and produces a list, not a change.** Separating them is the point: a task that audits *and* enables will report on its own work, and the enable step's design will bend toward whatever the audit found convenient. MS.1 ships a cleared list with evidence per row and touches no behaviour.
2. **"Which controls are safe" is a measurement, never a reading.** §1.4 is why: two of the eleven reach a `leagues` write through a helper, so the direct write set is not the answer; and §2.2 is why a `draft_*` sweep is not the answer either — two §8.7 *panel sections* reach league verbs that no draft-function query will surface.
3. **FOUR structural breaches, found by this survey, against the working draft's assumption of one — and the fourth is MIS-TARGETED rather than blocked, which is the worse shape.** `draft_reset` (writes `leagues.status` + `settings`, and broadcasts on `league:<id>`); the **autopick toggle** (`set_team_autodraft`, 072 — keyed on `p_league_id`, mocks explicitly excluded from its lock, writes the real `league_members.is_autodraft`); **seat reassignment** (the league's invite/assignment surface, embedded in the panel); and **`draft_set_order`**, whose mock refusal is real, sits in `prosrc` at `087:2341`, and **never fires** (§1.3). The first is a body that could be narrowed; the next two are breaches *by construction*; **the fourth cannot be fixed at the RPC at all**, because the RPC is never handed the mock. None has a mock-scoped version worth building (§10 item 4).
4. **AN RPC-LEVEL AUDIT CANNOT SEE A MIS-TARGET, AND THAT IS THE FINDING THAT GENERALISES.** At the RPC layer `draft_set_order(mock_id, …)` is genuinely mock-local: the guard fires, the composite comes back clean, and the control would be **CLEARED** — the breach lives one layer up, in a resolver an RPC-level audit never executes. This is why **MS.1 drives every control through its ROUTE, with a mock in the room AND a real draft alive in the same league** (§5 MS.1 item 3): without the second draft a mis-targeted write has nothing to hit and looks clean. §1.3's original heading — *"The API layer needs almost nothing"* — was the premise that hid it, and is corrected in place rather than deleted so the failure mode stays legible.
5. **The exclusion mechanism follows the breach's shape, not a house style.** Three of the four are excluded by an in-body refusal that names its own reason; the fourth is excluded by a **service-layer block plus a UI exclusion**, and neither half alone is one — §12's server-authoritative rule means a hidden menu item is not an exclusion when the endpoint still answers.
6. **Isolation has three dimensions, and a row count is the weakest.** Rows (whole-row composites, because three enabled controls UPDATE `draft_picks` in place), **broadcast topics** (`draft_reset`'s `leagues` write reaches every member's `league:<id>` subscription), and the whole-schema sweep as the net for a table nobody enumerated. §4 rule 10 states the standard; MS.6 builds the one harness that applies it.

The clock is what pause-first makes expensive — you cannot try a shorter bid clock without pausing, resuming, and losing the beat you were trying to feel.

3. **D141 and the ALIGN ruling are two events and must be cited as two.** D141 (PROGRESS §4) was enforced **auction-only**, with the snake divergence recorded and filed as **F57**. **Chris ruled ALIGN on 2026-08-18**, folded as spec §8.7 **v2.12.5** and built as migration **090 / L.C1.8**. #### D220 — `draft_reset` in a mock: the frame, the constraint, and the recommendation

1. **The decision is real, not a formality.** "Stays off" is defensible — *Delete practice & exit* already exists and a fresh mock is one click away.
2. **But delete-and-relaunch is rate-limited and lossy.** §22.5 caps mock creations at **5 per hour** per user (in-body, advisory-locked — D110(6)), so a launcher iterating on settings hits a wall; and a relaunch **re-seeds a `random` order** on the new mock's own id (D110(5)), so "run that same board again" is something relaunch cannot do.
3. **The shape is constrained by a measured fact, and it is not the obvious one.** A mock-safe reset **cannot** write `status = 'scheduled'`: `draft_start_internal` filters `is_mock = FALSE`, so nothing could restart it, and `draft-room.tsx:415` would render the real draft's lobby with a Start button that cannot fire (**F99**). The variant must land the mock **`live` at pick 1**.

1. **The ruling (Chris, 2026-08-20, after this document's first review):** *"so the point is the commish will need to set the draft order no matter, and it can always change last second. so there needs to be a way for the commish to set the order and then if real leagues can a mock league should as well so everyone can simulate their actual draft position or test different ones if they have a choice. for example, in my league last place gets to choose their draft position the next year."*
2. **The principle, stated so the lane can be tested against it: A MOCK GETS WHATEVER A REAL LEAGUE GETS.** Not *"whatever is safe to give it."* **A mock that cannot reproduce the user's actual draft position is not practice — it is a different draft.** §8.8 already said this about the engine (*"Same engine, literally… A mock that behaves differently from draft night is worse than no mock"*); D222 extends it to the commissioner surface, which is exactly what D103 had carved out.
3. **What it reverses, and it was the Architect's call rather than a Builder's slip.** The revision written after R468 excluded `draft_set_order` and put it on MS.5's must-not-render list. **Every piece of the diagnosis stands** — the mis-target, the probe, the never-firing guard. **The remedy answered the wrong question.** *"This control is unsafe"* is a reason to **fix** it, not to withhold it, and withholding it costs the user the one thing the motivating case needs. **Exclusion is now reserved for controls that write the real league BY CONSTRUCTION** (the autopick toggle, seat reassignment) **or whose product value is genuinely served another way** (`draft_reset` — MS.4's open decision, where "delete and relaunch" is a real substitute in a way that "don't set your order" is not).
4. **The fix is service-layer, and it is the shape §1.3 already identified.** `orderRequest` gains a `draft_id`; `patchDraftOrder` honours it; the mock room targets its own draft. **An RPC message change still cannot work** — the RPC is never handed the mock, so nothing it says is ever read. **MS.7** owns it.
5. **The severity note travels with the fix, and it is not about row counts.** A draft order is **negotiated property** — *"two people text messaging agree to swap picks."* Silently reversing one destroys an off-platform agreement **and posts a system line that makes it look deliberate**. That is why MS.7's pin is over the **real draft's stored order and its chat context**, not over a count.
6. **The control Chris named next does not exist, and it is NOT this lane's.** A **swap**: *"oh you like the 7th pick i like the 3rd pick. and then the commish needs to be able to swap them."* Filed as **F101** with the measurement that makes it a real gap. §6 says out-of-scope in as many words so it cannot creep in.

#### D223 — Choosing your slot at launch: the fast path, and why the seat picker cannot do this job

1. **The launcher already picks a SEAT, and that is a different question from a SLOT.** `mock-draft-launcher.tsx:138–156` renders a `Select` labelled *"Draft from seat"* (`aria-label="Seat to practice from"`) over `mockSeatOptions` (`mock-launcher-ops.ts:84–91`), defaulting to the launcher's own franchise (`defaultMockSeatId`, `:95–97`); the choice rides `config.mock.human_team_id`. **A seat says which franchise you play. A slot says when you pick.**
2. **And seat choice CANNOT be made to answer it — Chris's own correction is why:** *"there is no real draft order, most drafts will set the order right before."* `create_mock_draft` takes the real draft row's stored order as the candidate and resolves through the one implementation, **seeded by the MOCK's own id so an undrawn league gets a fresh deterministic shuffle per mock** (`089:935–957`, the comment says exactly this). So in the **normal** case — no order drawn yet — every launch reshuffles and the seat you chose lands wherever the shuffle puts it. **Picking a seat to get a slot works only in the minority case where an order already exists, which is backwards from how it will be used.**
3. **The task is therefore: choose your SLOT at launch — 1..N, default random — with the other franchises shuffled around you, written to the MOCK'S OWN order.** The real draft's order is neither read for this nor written by it, and is not required to exist.
4. **The fast path, deliberately — not a full order editor at launch.** `DraftOrderEditor` exists and works, and mounting it in the launch dialog would make someone drag twelve franchises into place to express *"put me third."* **The launch dialog answers one question with one control**; a launcher who wants a specific *full* order has the editor in the room once MS.7 lands. Recorded so the omission is not read as an oversight.
5. **Determinism is not optional and there is exactly one shuffle.** Reuse `draft_resolve_order_internal`'s existing seeding — the mock's own id (`089:935–957`) — rather than adding a second randomizer. Two implementations of "randomize an order" is the failure §4.7 exists to prevent, and a mock's replayability depends on it. **A slot choice is a constraint ON that shuffle, not a replacement for it.**
