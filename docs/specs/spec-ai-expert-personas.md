# Spec: AI Expert Personas

## Phase
Phase 0 (persona definitions + seeded lists) → Phase 1 (consensus integration via player matching)

## Overview

FieldScout ships with a roster of **AI expert personas** — fictional fantasy football analysts whose names parody well-known real influencers. Each persona has a profile, a distinct ranking personality informed by the real analyst's publicly known style and tendencies, and a set of AI-generated ranking lists (Big Board + position lists). Personas give new users instant content to browse, follow, and argue with before the human community reaches critical mass.

---

## Naming Convention

Swap the first letters of the first and last name, then append **(AI)** to the display name so users immediately recognize who the persona riffs on while understanding it is not the real person.

> Matthew Berry → **Bathew Merry (AI)**

Rules:

1. Swap the leading letter (or leading letter cluster where it reads better) of first and last name.
2. Display name always ends in `(AI)`.
3. Username is the swapped name in kebab/snake form with an `-ai` suffix (e.g., `bathew-merry-ai`) — never the real person's name.
4. The real analyst's name **never appears** in the persona's profile, bio, list titles, or rationale text. The resemblance lives entirely in the parody name and ranking style.

## Content Sourcing

Persona lists mirror the real analyst's actual published lists exactly, sourced only from free, non-paywalled pages:

1. **Ranked lists — exact mirror.** A sync script (FireCrawl) fetches the analyst's most recent published rankings from free public sources (e.g., NBC Sports for Berry, ESPN for Yates, Yahoo for Boone). The persona's list uses the **exact same players in the exact same order**. Raw scrapes are stored in `persona_source_rankings` with the source URL and publish date.
2. **Unranked themed lists — exact membership, renamed title.** Lists like "Sleeper WRs for 2026" are mirrored with identical membership but a renamed title in the persona's voice (e.g., "Underrated WR Targets for 2026") and `hide_order = TRUE` since the source carries no ranking.
3. **Original rationale text — always.** The analyst's written blurbs/analysis are protected prose and are **never copied**. Per-player rationales are generated by the Claude API from the FieldScout player data packet in the persona's `style_profile` voice. Ranks can be exact; words must be ours.
4. **Tendency profile (seed data).** Each persona keeps a structured `style_profile` (biases, voice, signature takes) — used for rationale generation and for any persona content with no direct source (e.g., positions the analyst hasn't published).
5. **Refresh cadence.** Re-scrape on the data-pipeline cadence (weekly in season, monthly off-season). Each refresh stores a snapshot (reuse `big_board_snapshots` pattern) so persona accuracy can feed the cred system later.

### Takedown process

If an analyst or publisher requests removal: set `is_active = FALSE` on the persona (or `deleted_at` on specific lists — soft delete per project convention). Persona lists disappear from feeds, consensus, and SEO pages immediately; no schema work needed. Keep `source_url` on every ingested list so any complaint can be traced to its source in seconds.

### persona_source_rankings

```sql
CREATE TABLE persona_source_rankings (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  ai_persona_id UUID REFERENCES ai_personas(id) NOT NULL,
  source_url TEXT NOT NULL,
  source_published_at DATE,
  position TEXT,                              -- 'Overall', 'QB', 'RB', ...
  scoring TEXT,                               -- 'PPR', 'Half-PPR', 'Standard'
  raw_rankings JSONB NOT NULL,                -- [{rank, player_name, team}, ...]
  scraped_at TIMESTAMPTZ DEFAULT now()
);

ALTER TABLE persona_source_rankings ENABLE ROW LEVEL SECURITY;
-- No policies: service-role only. Never exposed to clients.
```

## Data Model

Follows the existing expert-profile pattern in `03-DATA-MODEL.md`: personas are **application-level records, not Supabase Auth users**. Their lists are owned by the system expert account (`system_expert_owner_id`).

```sql
-- supabase/migrations/0XX_ai_personas.sql
CREATE TABLE ai_personas (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  username TEXT UNIQUE NOT NULL,            -- 'bathew-merry-ai'
  display_name TEXT NOT NULL,               -- 'Bathew Merry (AI)'
  bio TEXT NOT NULL,                        -- persona-voiced bio, includes parody disclaimer
  avatar_url TEXT,                          -- AI-generated cartoon avatar, never a real likeness
  style_profile JSONB NOT NULL,             -- structured tendencies (see below)
  is_active BOOLEAN DEFAULT TRUE,
  created_at TIMESTAMPTZ DEFAULT now(),
  deleted_at TIMESTAMPTZ                    -- soft delete, per project convention
);

ALTER TABLE ai_personas ENABLE ROW LEVEL SECURITY;
CREATE POLICY "ai_personas readable by all"
  ON ai_personas FOR SELECT USING (deleted_at IS NULL);
-- No insert/update/delete policies: managed by service role via seed/sync scripts only.
```

`lists` gains a nullable `ai_persona_id UUID REFERENCES ai_personas(id)`. A list is persona-owned when `owner_id = system_expert_owner_id AND ai_persona_id IS NOT NULL`.

### style_profile shape

```json
{
  "voice": "optimistic, story-first, loves a breakout narrative",
  "scoring_default": "PPR",
  "biases": [
    { "type": "upside", "weight": 0.8, "note": "ranks high-ceiling players above safe floors" },
    { "type": "narrative", "weight": 0.7, "note": "new coach, contract year, revenge game bumps" },
    { "type": "recency", "weight": 0.5, "note": "reacts to strong finishes to prior season" }
  ],
  "positional_leans": { "QB": "neutral", "RB": "slight fade", "WR": "favor", "TE": "favor elite only" },
  "signature_moves": ["round-early on hyped sophomores", "always has a 'my guy' sleeper"],
  "rationale_style": "one-liner with a hook, conversational"
}
```

The persona's `style_profile` replaces the `{style_description}` slot in the prompt template from `spec-ai-list-generation.md`.

## Phase 0 vs Phase 1

- **Phase 0:** Persona lists store player names as text inside JSONB (per `03-DATA-MODEL.md`). Personas + their Big Boards and position lists are generated by `scripts/seed-ai-personas.ts`.
- **Phase 1:** `scripts/match-expert-players.ts` resolves names to Sleeper player IDs and inserts `list_players` rows; persona lists then participate in consensus rankings (weight 1, same as cred-0 users).

## UI Requirements

1. **AI badge.** Persona profiles and persona-owned lists render a distinct `AI` badge (shadcn `Badge`, `variant="outline"` with a bot icon) anywhere the persona name appears — feed cards, list headers, consensus attribution, comments.
2. **Profile disclaimer.** Every persona profile page shows: *"Bathew Merry (AI) is a fictional, AI-generated analyst persona. It is a parody and is not affiliated with or endorsed by any real person."*
3. **No DMs / no follows back.** Personas can be followed but never initiate social actions.
4. **List attribution.** Persona lists are labeled "Generated by FieldScout AI" in the list detail view footer.

## Relationship to Claimable Expert Profiles

The PRD defines real-name **Expert Profiles** that can be claimed by the actual analyst (`expert_profiles`, claim flow, Expert Rankings Hub). AI personas are a separate, parallel system — and they resolve a conflict in the current docs: `01-PRD.md` says unclaimed expert profiles show *no* rankings, while `02-TECHNICAL-ARCHITECTURE.md` attaches AI-generated rankings to expert profiles ("claimed or AI-generated", `refresh-expert-rankings` cron).

Resolution:

- **Real-name expert profiles** (`expert_profiles`): claimable placeholders. **Never** carry AI-generated content. Rankings appear only after the real person claims the profile. (PRD wins.)
- **AI personas** (`ai_personas`): fictional, parody-named, never claimable, always AI-generated, always badged.
- The `refresh-expert-rankings` cron in `02-TECHNICAL-ARCHITECTURE.md` has been renamed to `refresh-persona-lists` and pointed at personas, and the `expert_profiles` description no longer says "or AI-generated". *(Applied.)*

This keeps the Expert Rankings Hub's promise ("only real rankings from real claimed experts — no AI-generated content") intact while still giving the app rich seeded content from day one.

## Related: Context Store & Content Engine

The continuously-refreshed per-persona knowledge layer (`persona_context` — the "context files"), the daily change-gated ingestion job (`ingest-persona-content`), and the automated persona posts/themed lists for SEO are specced separately in [spec-ai-content-engine.md](spec-ai-content-engine.md). That engine broadens persona content beyond exact ranking mirrors to context-grounded synthesized takes — under the same guardrails defined here: parody naming, original prose, free non-paywalled sources only, `source_url` retained on everything, and takedown via soft-delete.
