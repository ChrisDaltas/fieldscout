One golden test (e.g. the full DEFAULT_SEED stat line for one player per position, as literals) makes version bumps mechanical instead of honor-system.
- **R24 · should-fix · live-stats.test.ts:40 — refs: the falsifiability standard this batch claims throughout; §23.2.** The seam's game-window boundary is the one instant-sensitive edge in this diff with **no** boundary pin: tests run mid-window (18:00Z on game day) and 3 days out, never at `kickoffDay` exactly or `kickoffDay + 36h` exactly (live-stats.ts:163 — both edges inclusive). An off-by-one in either comparison (`>=`→`>`, `<=`→`<`) passes the suite. Two exact-instant cases close it; the window semantics are load-bearing for the finalization pass (`weeksToFinalize` gets `inWindow` from this check).

### Nit

- **R25 · nit · synthetic-stats-provider.ts:249 — refs: D25 ("provider-reported calendar day").** Synthetic derives `gameDate` from the kickoff's **UTC** day, so the SNF game (Sun 8:20pm ET) reports Monday `2026-09-21`, while the sleeper tier reports the ET day (checked-in 2025 fixture: Sunday games carry the Sunday date). Literally D25-compliant but a cross-tier semantic drift in the same field: composed with the seam's UTC-day-start+36h window it shifts a late game's window by a day vs. real data. Harmless on the current slate (earlier games open the window); worth aligning to the ET day before L.A0.6 composes synthetic with the seam.
- **R26 · nit · scenario-beats.test.ts:290 (D26 back-fill proof) — refs: §23.2 (back-fill on recovery).** Answering the brief directly: the outage-vs-happy_path equality is genuinely cross-scenario (it would catch PRNG streams keyed by scenario id, or outage state leaking into values — the two ways this provider *could* regress), but it is **not an independent computation**: both sides run the identical pure `finalLine`/`progress` code on identical inputs, and since the provider is stateless the equality is near-tautological. What §23.2 actually cares about — writer-side cumulative back-fill after a degraded window (upserts catching up in `player_stats`) — is untested anywhere in this batch and lands on L.A0.6. Fine for M0 provider scope; recorded so the gate task doesn't inherit "back-fill is proven" as a premise.
- **R27 · nit · scripts/record-fixtures.ts:90,99 — refs: D27 (identity lives IN the artifact).** The CLI hardcodes `provider: 'sleeper'` in the header and `sleeper.jsonl.gz` in the path instead of reading `provider.name` — re-introducing at write time exactly the guessing D27 exists to prevent. Equal today; a silent lie the day the CLI wraps any other provider.
- **R28 · nit · fixture-format.ts:68 — refs: D27 ("parse-rejected loudly on mismatch").** Loud rejection covers `format`/`version` only; a header missing `provider`/`season`/`week` parses fine and yields `name = 'fixture:undefined'` downstream.
