## 11. Spec questions & scope guard (the STOP rule, restated)

**If the spec is ambiguous, seems wrong, or a ruling conflicts with the codebase: STOP.** Write the question + evidence + options + recommendation to PROGRESS §3, raise a §5 blocker, and end the session reporting HALTED. The five questions below are all of a different kind — a verb with **no subject**, a **product** call about what an override means, and three **policy** calls nobody has made.

- **Q60 (NEW, filed with this PR — C61) — `commish_edit_record` HAS NO SUBJECT IN THE SCHEMA, AND THIS IS A REQUEST TO AMEND YOUR OWN RULING. BLOCKS ITS OWN TASK; blocks nothing else.** **Say the awkward half first:** standing rule **(d)** names this verb IN, by name — `PROGRESS-leagues.md:281`: *"**IN** — `commish_edit_score`, `commish_set_result`, `commish_move_player`, `commish_force_add_drop`, `commish_edit_lineup` (see (e)), **`commish_edit_record`**, `commish_change_setting`, plus `commish_rename_team`"*. Dropping it from M6A therefore **deviates from (d)** and needs Chris's word, not an Architect's. The reason to ask: `spec:1699` prints `commish_edit_record(team_id, w, l, t, reason)`, but W/L/T is a computed aggregate over `team_week_results.h2h_result` (`117:1065`); `teams.wins`/`losses` are written by no migration and read by nothing in the standings path (`001:501-502`); there is **no `ties` column** anywhere. Two honest constructions, both real design: **(a)** the verb edits the per-week `h2h_result` cells that sum to the requested record — which needs a policy for WHICH weeks absorb the delta, and interacts with `result_drift`; **(b)** a new `standings_adjustments` table that `league_standings` folds in — which must also answer what happens to Points For / Points Against, since the §7.3.7 tiebreaker chain reads them from the same rows. **RECOMMENDATION: (b)**, because (a) forges per-week history that the box score would then contradict. **This is not a refusal the standing rule converts to a defect — it is a verb whose subject does not exist**, so CLAUDE.md's STOP rule governs and there is deliberately **no §6 row**. **F337.**
- **Q61 (NEW) — ON A LIVE WEEK, DOES `commish_edit_score` SET `is_overridden`? Product call; blocks L.E1.5's copy, not its structure.** Setting it freezes the cell out of `score_write_week_batch` for the rest of the week (`119:634`/`:654`); not setting it means the next drain overwrites the commissioner within a minute. **RECOMMENDATION: set it** — the commissioner's number is the league's answer, and un-freezing is a second audited act — **and make the verb REPORT, in its result and its chat post, that live scoring has stopped for that matchup**, so the freeze is a stated consequence rather than a discovered one. Needs Chris because it is a product call about what an override *means* mid-game. A Builder may build the structure to this recommendation and swap the default in one line if he rules otherwise.
- **Q62 (NEW) — WHAT ORDERS AUTOPILOT'S CANDIDATES? Does not block L.E1.4; the sort is one isolated clause.** Placement is free (D340), so autopilot's entire selection policy is one sort key — and the honest position is that **no good weekly signal exists in the schema**. `players` carries only SEASON-TOTAL projections in three fixed scoring variants (`011_player_projections.sql:16-21`), which would contradict a league's custom scoring — the 2026 cohort's own stated feedback focus. That leaves `players.adp` (`002:15`), a DRAFT-DAY signal doing an in-season job, already the tiebreak-of-last-resort at the draft autopick's never-stall floor (`095:3484-3491`, the `ORDER BY pl.adp NULLS LAST, pl.id` at `:3490`) and in the sim's seating sort. **RECOMMENDATION: ship `adp ASC NULLS LAST, player_id ASC` as the DEFAULT with the sort isolated as one clause** (the `build for flexibility` preference — a weekly-projection input is later a one-line swap, not a redesign), and say plainly in the PR that this is a placeholder signal. The `AI rankings: fun, not perfect` memory applies: an autopilot lineup should feel reasonable, not be a source of truth. **Per the standing rule this is NOT a verb-refusal question and must not block the build.**
- **Q63 (NEW) — DOES AUTOPILOT SUBSTITUTE A STARTER A HUMAN ONCE CHOSE? Genuinely undecided; blocks only L.E1.4's substitution arm, not its fill arm.** A seat can be unmanaged today while carrying last week's lineup from a manager who left mid-season (`120:645-659` keeps the roster, `116:456` carries the map). Replacing a departed manager's **healthy, unlocked** starter with a higher-ranked bench player is a different act. **RECOMMENDATION: substitute ONLY when the seated starter carries a blocking designation or is on bye AND a healthy, unlocked, eligible replacement exists; never on value alone.** That is the narrow reading, it matches `spec:733`'s trigger word-for-word (*"officially OUT/inactive"*), and it keeps autopilot from silently out-managing the ghost of a real person.
- **Q64 (NEW) — DOES `rescore: true` REQUIRE `reopen_week` TO BE BUILT FIRST?
